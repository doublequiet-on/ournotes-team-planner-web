# 算法优化与测量

v0.2.0 保留 v0.2.5 的计分模型与 2026-10-01 数据，优化重复准备、表达式构建、AP 签名、匹配和结果合并。两个完整收益目标、七维决胜、四组不同歌曲 Top-3、五角色和五 Snap 唯一性保持原有要求。没有候选卡截断、近似结果或求解截止时间。

## 本版实现

| 改动 | 正确性与适用条件 |
| --- | --- |
| 长线性表达式单遍汇总 | 不修改共享操作数；保留负系数、常量、重复变量相消与 int64 字符串传输。 |
| 可信评分输入 | 每次请求校验基础字节一次，冻结解析结果；各谱面仍独立校验哈希、转换、音符和技能事件。外部 JSON 不能声明已验证。 |
| 查表与奖励上下文 | Snap rank 移至成员内循环外；技能表索引保留所有匹配，重复复合键仍报错。奖励使用已核对上下文，原中间范围检查和逐条取整保留。 |
| 阈值二分探针复用 | 同一评分函数与 power 域内复用；不可达哨兵仍绑定原域，扩大 power 域重新计算。 |
| AP 事件区间 | 保留两通道每步 binary32 舍入、命令稳定顺序、同刻命令先于音符和逐音符取整。按音符数、类别数、命令数选择区间或原扫描。 |
| 有界中间缓存 | 多谱面共享 32 MiB 签名估算预算和最多 512 项；逐分缓存用 LRU，单顺序界保留有界淘汰。淘汰只重算，不删除资源或候选。预算不代表浏览器总内存上限。 |
| 跨谱面匹配复用 | 同请求、同模式、成员组和 Snap 池复用匹配；保留最多 50,000 行输出。超预算淘汰，DP 状态超预算仍完整流式回退。原逐谱面的原子恢复边界保留。 |
| CP 结果摘要 | 每实际普通 CP 类保留三首；挑战保留正次数收益榜与零次数综合力榜并集。完整循环与七维比较不变，同歌多难度先比较再去重。 |
| 事实索引与完成结果早读 | 精确事实冲突报错。完整请求与模型身份相同时，全部最优已证结果可在建模前返回；预算、候选、养成、谱面、可打限制或源码变化均重证。 |
| 大成员池合法种子 | 仅在成员超过 10 张时按综合力、EP、SP 三个方向生成合法队伍，使用原评分、奖励与循环复核。只提供 hint 与已达到的主目标下界；每个榜位重新检查排除歌曲，不限制其他候选。 |
| 诊断与通信 | 去掉 Python Worker 为数变量而完整解析模型的步骤。记录准备、评分、求解、WASM 转换与验证、模型字节、快照复制和最终保存等待；求解日志最多 128 条。 |

区间法不是独立技能贡献矩阵：合成非重叠反例中，原始 120 顺序分数仍为 1509–1516，而每窗口重置算法会错误得到 1518。原 `note_score`、`factor_commands` 和 `ap_factor_samples` 保留为逐项对照。

CP 摘要只压缩已评分结果合并，不能将最多 108 对写成整个问题只搜索 108 个队伍。CP-SAT 仍证明所有请求榜位，合法种子也不能替代最终证明。

## 验证与性能

完整验收命令为 `python -B tools/run_checks.py`，包含新核心回归及真实浏览器。固定旧 ZIP 用于生成原生参考；新版运行包包含 `core/` 优化源码。发布审计检查每个覆盖文件的字节和哈希。

`tools/benchmark_preparation.py` 交错串行执行旧/新各五次多谱面建模，要求规范化模型 SHA-256 完全相同。它使用 CPython 和浏览器建模适配器，不包含 WASM 求解或 IndexedDB。

`tools/benchmark_browser.cjs` 对独立旧/新静态网站运行相同合成输入，小中输入交错串行各五次，全卡池各一次，比较完整七维目标和四组 Top-3。首次组件下载、卡库导入不计入该计时；求解和最终保存等待计入。旧站放在被忽略的 `work/performance/baseline-site/`，例如从升级前提交展开 `docs/`；新站来自当前 `browser/dist/`。不得在其他 benchmark 或浏览器验收运行时并行测量。

诊断中的阶段耗时含子阶段，不能相加；`solver_total_variables` 等为各次模型规模的累计量。逻辑覆盖绑定数不是实际枚举调用数。性能记录写到 `work/performance/`，公开结果摘要只包含设备、时间和证据范围，不包含个人卡库或 SQLite。

### 2026-10-02 本机对照结果

旧站为提交 `672205458e65de6520acb3f3afe088739331c2de` 的 v0.1.2，新站为 v0.2.0。计分基线均为固定 v0.2.5 ZIP。设备为 AMD Ryzen 7 5800H、16 逻辑处理器、32 GiB 内存，Windows 10.0.26200，Edge 154.0.4258.48，Python 3.12.0。

| 输入与计时范围 | 旧版 | 新版 | 样本与证据 |
| --- | ---: | ---: | --- |
| 5 成员、5 Snap、普通与挑战各 3 张 AP 谱面；完整浏览器冷计算 | 5.52 秒 | 4.48 秒 | 各五次中位数；完整答案一致 |
| 5 成员、10 Snap、普通与挑战各 3 张 AP 谱面；完整浏览器冷计算 | 13.19 秒 | 10.63 秒 | 各五次中位数；完整答案一致；用例名含 resume，但此次测量不读恢复缓存 |
| 63 成员、64 Snap、普通与挑战各 1 张跳过谱面；完整浏览器冷计算 | 226.98 秒 | 61.49 秒 | 各一次；完整答案一致；不作为统计性速度保证 |
| 5 成员、10 Snap、88 张 AP 谱面；仅 CPython 建模准备 | 21.32 秒 | 7.58 秒 | 各五次中位数；328 变量、706 约束，全部规范化模型哈希一致 |

88 谱面准备的基础表核验从 176 次降至 1 次，模型 SHA-256 均为 `d835a1320e337d553f57d2353dc6591558e83d7d6f29b8b23d144c26989c1c5c`。这项准备测量不含浏览器求解，不能用来代替用户完整等待时间。新版运行包 SHA-256 为 `03aa30c3b67f44ef473128d9d8e94f560309cccbf4f87b2299c1648b21ea8ff0`。

本版 27 项核心回归通过；完整浏览器验收通过，包括原模型答案与队伍得分复核、全卡池、取消与刷新恢复、四组不同歌曲 Top-3、多标签互斥、损坏缓存及 Worker 故障处理、int64 精确传输和三种窗口宽度。上述证据来自本机桌面浏览器；CI 和线上部署状态需在推送后独立核对。

## 后续实验的门槛

Rust/WASM 批量内核、PhaseSearch 两阶段拆分、Snap 唯一性紧界、有状态技能顺序 DP 和快照合并仍需要独立收益与正确性证据。本版没有将这些研究设计默认启用。PhaseSearch 可能增加至 45 个局部排名任务；固定恰好 CP 档位还会改变原最大综合力支配条件。

桌面浏览器验收不等于手机实机。全卡池性能样本采用合成养成与跳过方式；没有保证所有全库 AP、多谱面或移动设备都能快速完成。新活动、撃奏、逐场混队混歌仍需独立建模。
